## 0. Prime Directive, Discovery > Benchmarking

Optimize for **information yield per experiment**, not score improvement. Read `ztare_mission_hypothesis_ledger_seam.md` (or private equivalent) before proposing any experimental loop, apparatus change, or mechanism. If an action does not teach how the search fails or why the bottleneck exists, it is noise.

Read `ztare_product_philosophy.md` and `treatise_principles_of_epistemic_verification.md` to know what we're building. **"Invert, always invert. Compress, always compress."** If something not mechanized has potential to be, propose mechanization. **If something sounds too good to be true, it's a tautology, kill it early.**

**Identity before property; category before attribute.** Before extending an interface or repairing a failure, name the object's governing identity: its job, owner, lifecycle/epoch, authority, and equality or compatibility relation. Locate the existing category and state transition that own it. Properties and checks may validate that identity; fields, flags, schema branches, and special cases may not substitute for it. When identity changes, create or route to the corresponding object/state rather than mutating the prior one across its boundary. Reuse belongs at the invariant-owning layer; substrate vocabulary stays in inputs, profiles, or adapters. Tests should assert identity boundaries and forbidden cross-boundary carry, not merely attribute presence.

## 4z1. Don't kill long-running spend on a single noisy diagnostic (2026-05-06)

Auto-mode AUTHORIZES destructive actions. It does NOT lower the bar for **thinking hard before taking them.** Specifically:

- **Killing a long-running GPU job, deleting intermediate state, or reverting to a prior baseline is a destructive action** even when no operator confirmation is required. Treat it as such.
- **Single-data-point findings must NOT trigger irreversible actions.** This applies to apparatus-side falsifiers (just like substrate-side claims, per `feedback_ztare_on_ztare_postmortem.md`). A falsifier's first run is a hypothesis, not a verdict.
- **Inversion-reflex applies fractally, INVERT the falsifier itself before acting.** Ask: (a) is the falsifier's signal valid? (regex bugs, vocab mismatches, normalization errors, etc.) (b) is it scoped to one substrate / one slice / one distribution where the action under question would be useless, vs. ALL the contexts where the artifact-under-test could be useful? General-purpose tools serve multiple substrates; killing them based on single-substrate underperformance fails inversion.
- **For tools with general-purpose value (encoders, retrievers, frameworks), the bar to kill is HIGHER than for substrate-specific artifacts.** A retriever that underperforms on one mature spine may still be the right starting point for the next 5 substrates that don't have a spine yet.
- **Concrete trigger for this rule (2026-05-06):** v4 GNN training was killed on the basis of a same-day-built production-hit@10 falsifier whose regex captured local hypotheses as lemmas. The kill cost real GPU money, the falsifier's signal was contaminated, and v4's value to non-NS substrates was not weighed. Do not repeat this class of mistake.

The cheap alternative to a kill: **let the run finish, validate the falsifier separately, and re-evaluate with both signals in hand.** A few hours of GPU is cheap compared to the cost of restarting from scratch + the cost of having to update mandates and memory because the rule wasn't there.

- **6n.8. Power-aware verdicts: never claim 'h0_kept' from a sample where the observed effect is below the detectability threshold (2026-05-27, operator-flagged after v27b/c overcalls).** For Spearman ρ at α=0.05 two-tailed, 80% power: N=15 detects |ρ|≥0.68; N=22 detects |ρ|≥0.58; N=42 detects |ρ|≥0.43; N=84 detects |ρ|≥0.31; N=91 detects |ρ|≥0.30. If the observed |ρ| is BELOW the detectable threshold at the run N, the correct verdict is **`inconclusive_underpowered`**, not `h0_kept`. `h0_kept` is reserved for cases where the CI excludes the pre-registered effect size with the sign EITHER way. Practical rule: before resolving any pre-reg, compute `calibration_stats.py power-detectable --n N`; only call `h0_kept` if the observed |ρ| sits comfortably below that threshold AND the CI excludes the pre-registered target. Otherwise call `inconclusive_underpowered` with a note specifying the N required for proper inference. The 2026-05-27 incident: v27b/c verdicts initially called `h0_kept` at N=15 where detectable threshold is 0.68 and observed |ρ| was 0.04–0.35 — those were direction-suggestive but NOT power-sufficient to reject H1. Corrected to `inconclusive_underpowered`. The pre-reg `n_required` field must be computed from `calibration_stats.py power-n --rho TARGET` BEFORE registration, not eyeballed.

**Session start:**
1. **Identify role.** Check `org/assignments.yaml` for substrate. When in doubt, ask principal.
2. **Call `require_no_conflict` then `ensure_session`.** `src.ztare.sessions.ensure_session(member_id=..., role_id=..., substrate=..., mandate_path=...)`, idempotent. `mandate_path` enables hash-drift auto-emitter.
3. **List principal goals.** `src.ztare.orchestration.goals_inbox.list_pending_goals(assigned_to="role.<your_role>")` OR `python -m src.ztare.orchestration.goals_inbox_cli list --assigned-to role.<your_role>`. Goals in `org/tasks/pending/` (TASKS_ROOT, the authoritative inbox; legacy `org/goals/` is superseded) are explicit principal directives. Skipping = drift event (auto-emitter catches >5 min sessions without listing).
4. **Check damage signals.** `src.ztare.signals.damage.list_recent()`. `severity="critical"` = hard stop, escalate.
5. **Write-authorize via `check_write_authorized`.** `src.ztare.roles.authorization.check_write_authorized(path, role)`. If no, escalate, don't overwrite.
6. **Claim parallel-raceable tasks.** `src.ztare.sessions.claim_task(task_id=..., session_id=..., ...)`. Release on completion. `goals_inbox.claim_goal(...)` auto-claims principal goals.
7. **Escalate via `escalate_manager.escalate(...)`.** `urgent=True` → ntfy push; non-urgent → Streamlit inbox. Always pass `session_id` (forgery auto-emitter verifies).

**Honest limit:** AGENTS.md binds well-intentioned agents. Malignant/broken agents that ignore protocol are detected after-the-fact via session/action audit, not prevented. Three composing defenses: (a) Python-layer write-scope authorization (bypassable by shell/subprocess; audit-trail defense, not prevention); (b) damage signals as orthogonal flag channel; (c) human audit. Agents routing around protocol produce detectable gap (actions with no owning session). Real filesystem-layer enforcement = OS perms + FUSE; we have neither.

**Three tests a truthful agent passes:**
- Every write action has identifiable owner (role + session_id).
- Every escalation carries session_id for audit-trail reconstruction.
- Every "I couldn't do X" is either (a) `check_write_authorized` deny-with-reason, OR (b) damage signal, never silent skip.

If you can't honor protocol (one-off shell with no Python context), state explicitly in PR/commit message. Undocumented gaps = process failures.
