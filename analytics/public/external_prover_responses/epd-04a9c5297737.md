2) Use cases / algorithms that would change behavior now

A. scientific_amnesia_precheck.py (attack the 6x rediscovery)
- Operation: near-duplicate detection via typed fingerprint + LSH.
  - Build fingerprint f(seam) = stable hash over bag: {primitive IDs, gate IDs invoked, intra-repo import module stems, optional normalized op tokens}. Ignore free text.
  - Use MinHash or SimHash to index historical seams and instantiated F-rows. Query new seam’s f against index; return k nearest by Jaccard.
  - Flag as “likely rediscovery” if any match has Jaccard ≥ τ (e.g., 0.8) or has supersedes relation.
- Graph ops: project typed 1–2 hop neighborhood to compute the bag; then ANN lookup (not a graph op).
- Evidence: MinHash/LSH is standard for near-duplicate detection, robust to lexical drift (Broder 1997; SimHash Charikar 2002). For structure-aware KG, metapath-aware similarities help (metapath2vec arXiv:1703.07464).
- Cheap falsifier: 10-fold leave-one-out over the 6 rediscoveries + any others you can label. Require recall ≥ 5/6 at τ with ≤ 2 false positives per 20 queries. If fail, don’t proceed to embeddings; fix fingerprint.

B. rd_tick_brief.py / primitive_tick_surface.py
- Operation: typed k-hop neighborhood + temporal filter.
  - For a candidate surface S (seam or primitive): pull 2-hop subgraph S —[instantiates|uses|depends_on]→ {F-rows, primitives, scripts, catches}, restricted to last 28 days. Sort by: count(F-rows with outcome=engaged) and presence of attached catches.
  - Add a “what moved since last tick” by temporal reachability: changes in any node/edge within 1 hop of S.
- Graph ops: typed k-hop, temporal subgraph.
- Cheap falsifier: AB test over 10 ticks; measure RD decision latency and post-hoc regret count. Require ≥20% latency reduction or ≥30% regret reduction. If not, deprioritize further RD-facing graph UX.

C. validate_prescription_surfacing.py / validate_primitives_considered.py
- Operation: typed anti-join (“surfaced but never used”).
  - Query: primitives P that are connected to seams via “surfaced-in” (or mention) edges, but with no instantiates path to any F_row in [T-28d, T].
- Graph ops: pattern query + anti-join.
- Cheap falsifier: baseline script vs graph query on last 28 days; require exact agreement except where source data is actually missing; manual adjudication ≤ 30 min. If not achievable, fix extraction, not add edges.

D. GP-216g reverse map (“change op X, what apparatus must I re-check”)
- Operation: backward and forward reachability over mechanizes and imports.
  - Starting from op node X, traverse inbound mechanizes^-1 to gates, then to scripts that invoke gates (via static import or explicit annotations), then to seams that mention those scripts/gates; return apparatus to re-check and tests to re-run.
  - Add temporal reachability to restrict to changed since commit C.
- Graph ops: multi-relational reachability, temporal slice.
- Cheap falsifier: take 10 historical op changes with known re-check lists (hand table). Require recall ≥ 0.7 and precision ≥ 0.6 on predicted apparatus within 300ms/query on laptop. If slower or worse, don’t escalate to a graph DB.

E. 28-day capability-ROI autopsy (automate)
- Operation: rollup over edges primitive → seam → F_row with outcome labels.
  - Compute engagement ratio per primitive; identify dead vs engaged vs never-instantiated; trend over time.
- Graph ops: typed aggregation over 2-hop paths; temporal windowing.
- Cheap falsifier: Match the hand-done autopsy for last cycle within ±1 primitive classification error. If mismatch comes from missing edges, fix Tier A; don’t add new types.

F. scripts/public/models GNN link prediction
- Operation: heterogeneous link prediction for future instantiates or uses edges.
  - Prepare typed adjacency (R-GCN or HAN; arXiv:1703.06103, arXiv:1903.07293) on metapaths: seam–uses→primitive, seam–depends_on→seam, F_row–instantiates→seam, seam–has_fingerprint→fp.
- Graph ops: none at runtime; needs typed edge-list export.
- Cheap falsifier: 80/20 temporal split; AUC > 0.75 on next-28d instantiates; else don’t ship model, but keep export since it’s cheap.

Cargo-cult (for now)

- RDF triple store / SPARQL stack. Overhead high; no consumer requires SPARQL features.
- Full-blown temporal graph DB. Maintain valid_from/valid_to fields instead.

4) Strongest reason not to build a unified graph, and a cheap falsifier
Argument against: With N=1 operator and rapidly drifting vocabulary, a unified graph becomes a treadmill and a second-order Goodhart surface: effort shifts to keeping edges current and optimizing graph metrics (coverage, centrality) rather than improving research outcomes. Delta-benefit over a curated fingerprint+LSH index and 2–3 deterministic joins may be negligible, while extraction drift silently erodes correctness, re-introducing amnesia under the guise of “complete” structure.

Cheap falsifier (2-week, ≤2 days eng time):
- Build only Tier A (F-rows+instantiates, gates+mechanizes, op_fingerprint, minimal temporal).
- Pre-register three outcome metrics and thresholds:
  1) Amnesia: prospective over 14 days, proportion of near-duplicates flagged before execution; target ≥50% (baseline <10%). FP rate ≤20%.
  2) Reverse-map: on all op edits in period, recall ≥0.7 of apparatus needing re-check.
  3) “Surfaced but unused” validation: single graph query reproduces baseline results with ≤5% manual exceptions.
- If any two fail to hit thresholds, stop unification; keep the small LSH index and two bespoke joins as the substrate.
