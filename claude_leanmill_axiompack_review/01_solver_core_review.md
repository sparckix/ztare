## Findings

**F1 — Ratification stamp fail-open on outer governance crash (solver_core.py:5204-5222).** Inner organ crash correctly sets `integrity_unverified=True` → ratified=0 (5123-5129). But an exception anywhere in the outer governance block (e.g. artifact-identity resolution 5044-5074) lands at 5204, sets `res["governance"]={"error":...}` with no `integrity_unverified`, so `_gov_verified=True` at 5216 → **ratified=1 and `VerdictKind.CLOSED` emitted (5293) for a closure whose statement-integrity/margin organs never ran** — contradicting the adjacent stated policy (5209-5214). Backstop: solve-time authoritative kernel already ran — but it is also fail-open on crash (1567-1569); if both crash, a closure is ratified with zero anti-laundering audit. One-line fix: set `integrity_unverified` in the 5204 except.

**F2 — Decomposition parent closures skip the entire closure epilogue.** Decompose-first early return (solver_core.py:5007 → `_decomposition_closed_result`, 4490-4496) and post-cascade iso lift (5471-5487, running after the cert/deposit/bank blocks) produce `outcome="closed"` with: no closure certificate, no proof-cache deposit (5318), no family/env rung banking (5335), no ratified stamp (5215). Soundness holds (composite_ratify runs the same kernel), but this is the repo's documented "banking never fires" amnesia class recurring for parent rungs — next run re-derives the parent; the cert audit chain has a hole. Also the decompose-first pre-pass (4999-5009) runs **outside** the `clean_capability` reference-leakage quarantine (entered at 5010), yet reports `quarantined_references: []` as if clean — a capability-claim receipt hole.

**F3 — Preverified champion silently dropped in dag_search mode (solver_core.py:3958-4063).** The `_pvp` governance door exists only in the cascade branch; the dag branch (3628-3828) `continue`s before it. Comment at 3966-3968 ("every current caller runs cascade") is stale: workbench_actions.py:682 (CLI default), autoformalize.py:2010, autoformalize_notes.py:457, isomorphism_decompose.py:909 all pass `mode="dag_search"`. Pool champion (set at 4869) and external preverified proofs discarded and re-derived — the 2026-06-22 "pool-closure-drop" bug re-opened along the dag axis. Economics loss, not soundness.

**F4 — DAG cache-reuse closures carry a false MNC receipt (solver_core.py:3823-3826).** Any dag root close is stamped `matched_negative_control: executed_at: "solver_layer"`, but the cache-reuse door (governed_dag_search.py:1458-1506) closes on compile-only re-verify — no MNC ran. Partially compensated post-hoc; still a receipt-integrity mislabel.

**F5 — Cache keys (the recurring repo defect class): acceptable.** proof_cache keys on α/∀-normalized statement or kernel Expr-type-hash; env hash recorded but not in key — sound because both use sites re-verify in-context. Warts: `put()` dedups on statement key alone (proof_cache.py:262) so a first-banked env-A proof permanently shadows env-B's own proof (guaranteed re-verify-fail churn); `ProofCache.get` returns proofs even on `context_mismatch` (218) — sound but forecast-credit-distorting (its own comment admits). no_good_store reuses the same key function (single door, correct), requires `confirmed=True`. fix_memory prompt-inert (safe) but plain unlocked append (fix_memory.py:66) unlike the flock'd door elsewhere.
