# Review — LeanMill campaign/orchestration layer

Scope: ~31k LOC (frontier_campaign_runner.py 9,828 lines via targeted sections + its full 1,809-line uncommitted diff; full reads of campaign_closure_gate, audit_external, frontier_boundary, frontier_campaign_actions, formal_task_campaign_executor, formal_task_boundary, external_science_admission, typed_exit, phase_timing, work_queue, run_observability, state_convergence, verdict_store, + rest of focus list; providers/adapters skimmed) + live receipts in analytics/public/. The two most severe claims independently verified.

## Soundness verdict on the two doors

**campaign_closure_gate.py — sound as specified, but it guards consistency, not kernels.** The gate (:870-956) is content-bound, replay-verified, fail-closed, and enforced: every stop transition in `next_frontier_campaign_action` (frontier_campaign_runner.py:9459-9594) returns `complete` only when the gate is ready; `retired_unresolved` correctly non-credit; no env bypass. But `objective_discharged` reduces to replaying adjudicators over a boundary row's recorded `kernel_checked: true` — the gate never recompiles or re-audits. Its floor is boundary-row production, which has two real holes (findings 1-2). Also the gate silently vanishes when `_frozen_terminal_lineage_ids` (:9096-9105) returns empty — gate presence depends on producer-controlled run.json shape.

**audit_external.py — allowlist correct, but the probe can be silenced, and nothing calls it.** `ALLOWED_AXIOMS` (:30) byte-identical to solver-side `AXIOM_ALLOWLIST` (gates/lean_compile_primitives.py:44); lexical ban and non-compile path fail closed. Two problems: (a) **vacuous-pass** — at :79-86, if `decl_blocks` finds no decls the axiom audit is skipped; if the appended `#print axioms` probes produce no output while the compile "succeeds" (a `#exit` in the artifact, or the module-incompatibility class from the past RCA), `parse_axioms("")` returns `[]` and the artifact passes — a `native_decide` proof + `#exit` fully evades the gate. `proof_audit.py:423-451` already has the fix shape (`axiom_probe_satisfied`: probe must cover every decl); audit_external lacks it. (b) **Unwired** — zero callers in src/; neither external_science_admission nor formal_task_campaign_executor routes through it.

## Findings (severity-ordered, verified)

1. **Banned-axiom rejection laundered back into closure evidence (LIVE lane).** `lean_consequence_bridge.py:449-458`: when the solver returns `rejected_banned_axiom` but proof bytes exist, the bridge re-governs via `recheck_governed_lean_consequence`, whose whole audit is `has_sorry` + textual `axiom`-decl scan (:200-205) + `_compile_probe` (compile-only, "SORRY IS ALLOWED... BY DESIGN", no `#print axioms` — v33_preflight_risk_detector.py:303-320). Grep-verified: zero axiom-audit machinery in that path. Scenario: a `native_decide` proof the solver's organ correctly rejected returns as `proved_attributed`, becomes a `kernel_checked` boundary row, discharges the objective, passes the closure gate.
2. **The formal-task lane has no axiom leg at all.** `formal_task_campaign_executor.py:928-943` requires `kernel_compile_receipt.passed` + `matched_negative_control_receipt.passed` but never checks `axiom_allowlist_receipt`/`axiom_tier` — the fields its sibling `external_science_admission.py:397-409` demands (`kernel_pure`). Solver-side audit is fail-open on tooling error (solver_core.py:1607-1608, verified); `require_positive_axiom_receipt` defaults False (:1343); the executor's "independent kernel replay" is compile-only; no lexical ban on `axiom` decls in admitted source. End state `kernel_verified_independently_reviewed` (:1040) can be minted with zero axiom audit anywhere in the lane.
3. **Recompilation is advisory.** The only re-elaboration of saved proof bytes, `recheck_frontier_boundary_governance` (:6828-6957), is fire-and-forget (:6786-6791); outcomes surface only as a count; nothing in the discharge path consumes them. A row whose recheck says `proof_rejected_by_kernel` still discharges.
4. **Receipt identity weak at three layers** (verified live). Workbench result files bind to jobs by path string only — no job id key, no artifact hash; specs mutated post-run (2 of 3 pairs silently rewritten Jul 15, 14 days after finished_at). `kernel_parity.jsonl` (113 rows): exactly `target, hand_wired, kernel, kernel_blocked` — no timestamp/hash/run id — consumed by external_science_admission by target-name lookup (:414) from submitter-chosen files (:303-318), unsigned. 777 closure certs content-hashed but `run_id` in 0 of 777. Mitigation: external-science admission is hard-typed `resume_context_only`, closure/discharge forbidden (:61-63, 1776-1779) — blast radius is resumed search, not credit.
5. **The P0 timing RCA is re-opened for this lane.** `summarize_campaign_cycle_time` computes correct `wall_s` but keeps `time_to_closure_s` as a prove-window-only alias (phase_timing.py:331); the launch marker `record_campaign` is only stamped by `autoformalize_notes.py:2455`, never the frontier runner, so the fallback (:307-308) reproduces the old under-report; both consumers read the prove-only field (factory_intelligence.py:4765-4782, forecast_router.py:581-584); `theory_task_executor` tags work `run_tag+"-formalize"/"-solve"` (:6704,6711) so exact-match aggregation shows nothing for the lane that discharges. No measured end-to-end time-to-closure exists anywhere in analytics/public/queries; 1,558 of 8,699 phase-timing rows have empty run_tag.
6. **Typed-exit laundering, three spots.** (a) typed_exit.py unused by the frontier layer — parallel status vocabularies. (b) Boundary catch-all `unresolved` buckets infra failures (dead compiler, timeout) with genuine survivals (`_BOUNDARY_FAILURE_STATUSES` :3284-3291 excludes them) while routing tells the leaf to "treat boundary survival as evidence" (:4341-4344) — a calibration-free negative (the standing rule: a negative is inadmissible without calibration). (c) A charged interpreter crash becomes a durable `interpretation_inconclusive` receipt permanently satisfying the interpretation obligation (:8898-9061); `retry_inconclusive` exists but the autonomous drive never uses it. Also typed_exit.py:265-266 grants `unratified_closure_candidate` when any round compiled, not when the target closed (dashboards over-count; `credit_status` containment holds).
7. **Uncommitted-diff conflict: budget-extension reopen vs immutable dispositions.** New reopen machinery (:2566-3023) makes a budget stop reversible, but dispositions minted at the first post-stop drive (:9533-9549) are write-once (:9077-9078 raises on change). Scenario: stop → dispositions minted → operator extends budget → boundary genuinely discharges → conflicting disposition raises and wedges the campaign; the honest discharge can never be recorded. Sharpest symptom-vs-root-cause item in the diff: reopen bolted on without a disposition-supersession path.
8. **State-laundering plumbing.** work_queue.py:503-518 — re-enqueue of a `done` work_id is a silent success no-op (stale payload stands); `update_status` (:1237-1267) permits failed→done with no state machine. state_convergence.py:296-321,376-378 — cross-node merge of solver_lane_attempts.db keys on non-unique `row_id`, dropping all of a node's rows for a target the other node has (merged ledger can show a closed target as failed). verdict_store.py:69-76 + run_diagnostics.py:236 — empty run_tag summarizes the entire historical ledger into the current run's verdict block.
9. **Diff loosened a review binding.** generative_representation.py:196-200 changed per-ref `canonical_sha256_ref` (exact digest identity) to `extract_sha256_refs` (harvests digests embedded anywhere in arbitrary strings); the new `host_conformance_contract` self-replays from its own stored payload (:42-49, 258-265).
10. **Wiring hazards.** `first_order_baseline.py` untracked yet imported top-level through theory_interest.py:14 into five module chains incl. the CLI — a deploy missing it breaks `leanmill` entirely. `resume_runtime_preflight.py` is `python -m`-only — the transition-surface preflight never runs in any campaign flow. `retire` accepts any non-empty authority string (frontier_campaign_actions.py:892-934) — bounded (mints only `retired_unresolved`).

## Iatrogenics

Not three parallel campaign shells (deterministic_frontier_campaign is a no-provider control; formal_task_campaign_executor is a boundary callback — they layer). The real overhead: the runner is ~4:1 governance-to-proving (221 `receipt_sha256` mentions, 85 schema literals, ~1,000-1,500 lines of actual orchestration); `_frontier_lifecycle_marker` (:9597-9648) re-SHA256s every artifact in the attempt dir on every drive iteration; one synthesis decision lives in four or more artifact families; of the ~9.2k-line plumbing layer roughly a third is telemetry-on-telemetry (typed_exit shadow contracts, control_plane_audit duplicated item lists, run_observability double-reading four ledgers, work_queue running `git status` + full source re-hash twice per claim).

## Top 3 remediations

1. **One axiom-audit chokepoint for closure evidence.** Require a positive `axiom_allowlist_receipt` (`axiom_tier == "kernel_pure"`) wherever closure evidence is minted: stop the `rejected_banned_axiom` upgrade in lean_consequence_bridge.py:449 (or make the recheck run the real `audit_axioms_subset`); add the axiom-receipt check to formal_task_campaign_executor.py:928-943 mirroring external_science_admission.py:397-409; make audit_external fail closed unless every decl appears in probe output (borrow proof_audit.py's `axiom_probe_satisfied`). Three small diffs at existing seams; closes findings 1, 2, and the audit-door hole.
2. **Close the timing under-report at both ends.** Stamp `record_campaign` at frontier campaign launch; switch factory_intelligence + forecast_router from `time_to_closure_s` to `wall_s`. Until then every quoted P0 time-to-closure from this lane repeats the 2026-07-01 RCA.
3. **Bind receipts to identity, and commit the missing file.** Result files echo job_id + source_sha256; kernel_parity.jsonl rows gain timestamp + source hash + run tag (weakest link, trusted by name); closure certs gain run_tag. And `git add src/ztare/leanmill/first_order_baseline.py` before anything else — one command to remove a break-the-CLI deploy hazard.

Pre-ship for the reopen machinery: a disposition-supersession path (finding 7), or the first extended-budget campaign that genuinely discharges will wedge.
