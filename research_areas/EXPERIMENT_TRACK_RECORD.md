## Status

## Why This Exists

ZTARE already has three partial reporting surfaces:

- seam-level debate logs
- board rows
- project-local run artifacts and synthesis ledgers

What it did not have was one simple place a cold reader could inspect and answer:

- what experiments actually ran?
- what did the repo learn?

This file is that surface for the **canonical view**. It is intentionally lighter than a paper and more durable than chat. This is the single source of truth. No separate private mirror.

This file is **not** a replacement for:

- seam files, which remain the source of debate history
- `ZTARE_BOARD.md`, which remains the source of in-flight prioritization
- project-local artifacts, which remain the source of run-level provenance

It is the compressed cross-program track record.

## Update Rules

1. **This file does not track live hypotheses.** Pre-run hypothesis discipline lives in seams and seam-local ledgers.
2. **Experiment rows (`E-...`)** are added when a run closes, is operator-stopped, or otherwise yields a stable conclusion.
3. **Experiment rows carry a `Recorded` date** so later readers can audit when the row entered the ledger.
4. **Finding rows (`F-...`)** are added only when an experiment changes what the repo should believe or build next.
5. **Public mirror discipline:** only shipped / closed / public-safe rows belong in `research_areas/EXPERIMENT_TRACK_RECORD.md`. Everything else stays private until promotion is admissible under the visibility rule.
6. **No hypothesis backfill:** retrospective explanation belongs in seams, not in this track record.

## Findings Recording Procedure (added 2026-04-19)

**When to record:** After any sandbox run reaches final score OR is frozen, before starting the next experiment. Staleness accumulates if this is deferred.

**Three artifacts, in order:**

1. **EXPERIMENT_TRACK_RECORD.md (here)** — one E-row per run, one F-row per confirmed finding. Must be written before or immediately after the run closes. E-rows require: date, substrate, model pair, iteration count, outcome classification, champion expression if applicable, cost. F-rows require: the claim in one sentence, confidence tier, implication for what to build next.

2. **insights_ledger.md** — one INS-NNN entry per finding that meets the "would go in a paper Results section" bar. Requires: claim, evidence pointers (seam + run artifacts), confidence tier, paper target, status. Do not open an insight for an observation that changes nothing.

3. **GP-103 / relevant seam** — postmortem section when architectural findings emerge from the run (new failure mode, new trigger guard flaw, new pattern). Seam postmortems are longer than ledger entries and include causal chains, panel assessments, and fixes.

**What makes a finding stale:**
- Run completed but no E-row added → stale
- E-row present but no F-row for a confirmed finding → partially stale
- F-row present but not reflected in insights_ledger.md → stale at insight layer
- Seam postmortem missing for architectural findings → stale at diagnostic layer
