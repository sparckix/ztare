# Predictive history lift

Date: 2026-07-25

Parent tick: `tick-arc3-consumer-indexed-exception-frontier-20260723`

## Eigenquestion

Does lifting the partial-action source from a frame to
`(frame factors, bounded action-history state)` eliminate the boundary
counterexamples that are impossible to separate from the current observation?

## Hypothesis

A history suffix is a finite recursively updated state, unlike an exact trace
index or cumulative count. Select the shortest suffix length on the current
evidence that:

1. separates every admitted boundary/law consequence pair sharing the frame
   projection;
2. reaches the minimum observed ambiguity count among bounded suffixes;
3. retains more quotient compression than exact counters.

The initial flattened-bank audit selected length 12. A subsequent identity
check ruled that store incompatible with history claims because it lacks
trajectory prefixes. The live-equivalent sealed-lineage audit selects length
1, removes every boundary-contaminated non-commutation, and proposes a
two-action frontier route. The selected length remains evidence-derived and
must remain a parameter of the history projection, never a substrate
constant.

## Discriminating checks

1. Reconstruct suffixes per continuous trajectory; reset only at an
   evidence-backed lifecycle boundary or trajectory discontinuity.
2. Verify recursive update under each operation.
3. Retain witnessed history/frame representatives as the section.
4. Recompile boundary and law observations together and report ambiguity,
   fibers, and frontier.
5. Supply the verified seed/action prefix to live planning so the start key
   uses the same history chart as evidence rows.
6. A subsequent no-worker probe must produce a level event, a frontier
   observation, or a history-lift counterexample without reusing a relation
   already ambiguous under the lifted key.

## Kill conditions

Reject or refine the lift if:

- suffix length is hardcoded to the current game;
- trajectory segmentation uses task knowledge;
- live history and evidence history use incompatible reset rules;
- the lift fails recursive update;
- ambiguity is hidden by making each evidence row unique;
- a known ambiguous lifted relation is used as an open-loop traversal edge.
