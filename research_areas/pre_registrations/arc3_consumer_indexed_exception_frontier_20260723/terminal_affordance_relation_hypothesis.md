# Terminal affordance-relation transport hypothesis

Date: 2026-07-26

Hypothesis ID: `H-ARC3-TERMINAL-AFFORDANCE-RELATION-20260726-28`

## Eigenquestion

Is prior task discharge attached to a presentation-invariant relation among the
controlled object, its configuration, and the destination attempted by the
terminal intervention?

## Hypothesis

The two prior completion edges share an exact terminal affordance descriptor
after removing palette names, absolute position, and global lattice
orientation. The descriptor includes the controlled object's current finite
configuration and the static neighborhood at its action-conditioned attempted
destination. It will recover the held-out epoch-1 completion and exclude every
same-epoch non-discharge terminal edge.

## Governing identity

The tested object is a `terminal affordance relation`: one source state, one
intervention, an evidence-derived operation-to-displacement map, one attempted
destination, the controlled object's configuration, a bounded structural
neighborhood, and exact lineage.

The terminal lifecycle edge and task consequence remain separate fields. The
relation is advisory and has no authority to rewrite an ordinary transition or
declare completion.

## Fixed lowering

For each source epoch, infer each operation's displacement from ordinary
controlled-base translations in the exact boundary-anchored sections. A
terminal operation is usable only when its modal displacement has support at
least two and strictly exceeds every alternative for that operation.

At each terminal source:

1. require a unique controlled-base origin;
2. add the inferred displacement to obtain the attempted origin;
3. extract the attempted footprint and a square neighborhood with margin equal
   to the controlled object's maximum dimension;
4. mark current controlled-object cells and out-of-bounds cells by structural
   roles;
5. replace all remaining palette values by their equality partition;
6. choose the lexicographically least image under one global dihedral
   transform;
7. pair each geometry code with the equality partition of
   `finite_configuration`.

Evaluate four fixed descriptors: footprint only, footprint plus
configuration, shell only, and shell plus configuration.

## Discriminating test

Use the epoch-0 completion descriptor as the sole template. Hide the valence of
all epoch-1 terminal edges, compare exact descriptor equality, then reveal the
labels. Report operation-map support, the selected global symmetry, descriptor
preimages, and exact source/evidence lineage. Geometry-only variants are
configuration ablations; configuration-only equality is a geometry ablation.

## Success criterion

Both positive edges have admissible displacement maps and unique controlled
origins. At least one geometry-plus-configuration descriptor matches the
held-out completion exactly, no non-discharge terminal edge shares it, and the
match survives palette renaming and one global dihedral transform with complete
lineage.

## Kill condition

An operation displacement is unsupported or tied; controlled origin is
ambiguous; no exact positive match; a failure shares the descriptor; matching
requires absolute coordinates, literal palette values, literal operation
names, separate rotations for subregions, path history, or hidden valence; or
lineage is incomplete.

## Claim boundary

A pass certifies a prior-level terminal-affordance correspondence only. A
separate Level 3 consumer must prove that any nominated edge has this relation
before execution, and only the adapter may report task discharge.
