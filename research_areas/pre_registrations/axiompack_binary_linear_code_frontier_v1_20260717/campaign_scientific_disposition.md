## Representation and certificate boundary

The registered `binary_linear_code.v1` adapter can normalize a proposed
generator, prove rank over `F_2`, enumerate its codewords, and return an exact
minimum-distance witness. The campaign also emitted a proposal-only successor
language request for the mismatch between anonymous theory presentations and
the reviewed witness-construction interface. That request was not compiled
into an admitted successor capability in this run.

The published `[51,20,14]` control confirms a separate formal-certificate
capacity boundary. Native bit-vector normalization can decide the finite
statement, but the generated native-check axiom is outside the ratification
allowlist. Direct kernel-pure LRAT import remained too large for the observed
elaboration envelope. The next certificate class is either chunked
kernel-pure LRAT elaboration or a structure-aware algebraic certificate with
an explicit reflection link. This is a certificate-producer gap; it does not
justify changing the common ratification policy.

## Scientific result

The mathematical discovery count for this run is zero. The useful outputs are
an exact null result over six proposals, a replayable construction frontier,
and a sharper separation between search, deterministic domain verification,
certificate production, and final ratification. A successor campaign should
search a declared structured construction space and reuse the recorded
counterexamples. It should not resume by asking a language model for unrelated
raw generator matrices.
