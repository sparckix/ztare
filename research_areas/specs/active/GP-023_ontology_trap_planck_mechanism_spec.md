# GP-023 Ontology Trap / Planck Mechanism Spec

## Status

Active

## Scope

- define GP-023 Phase 0 only
- turn the ontology-trap seam into a runnable but not-yet-executed experiment plan
- specify the pre-registration, contamination audit, and sandbox-construction blueprint

Does not cover:

- executing the sandbox run
- interpreting a finished run
- product-level storytelling based on hypothetical outcomes

## Decision

GP-023 should begin as a Phase 0 research artifact set, not as an immediate live run. The right move now is to freeze the first-run evaluation contract in a pre-registration document, write a clean implementation blueprint for the sandbox/conduct rules, and stop there. Do not construct or execute the ontology-trap sandbox until the contamination audit procedure and scoring protocol are fixed in writing.

## Problem

ZTARE has been carrying a philosophical claim about its own limits:

- maybe it can only surface structure, not invent new ontology
- maybe the Planck-style mechanism is impossible
- maybe the question is unknowable in advance

The seam correctly reframed that as the wrong category. This is not mainly a philosophy problem anymore. It is an experiment-design problem.

But without a frozen protocol, GP-023 would be too easy to contaminate and too easy to over-interpret.

## Why It Matters

If GP-023 is real, it changes the ceiling on what ZTARE might be able to do under extreme constraint.

If GP-023 fails cleanly, it closes an important frontier and sharpens the product philosophy.

Either way, the result is only valuable if it is:

- uncontaminated
- pre-registered
- mechanically scored

Otherwise it becomes a self-deception engine.

## Constraints

- do not run the sandbox yet
- do not use recognizable historical physics vocabulary
- must separate contamination audit from sandbox execution
- must keep scoring mechanical rather than operator-vibes-based
- must use the current GP-021 profile behavior, not an imagined prompt

## Options

### Option A — Run The Sandbox Immediately

**Description**

Start a black-body-inspired sandbox now and see what happens.

**Pros**

- fast feedback
- exciting if it works

**Cons**

- contaminated positive is uninterpretable
- success criteria would drift after the trace is visible
- high risk of retrieval theater

**Verdict**

Rejected.

### Option B — Keep Debating The Philosophy

**Description**

Leave GP-023 in the seam only and keep refining the argument.

**Pros**

- no engineering overhead
- avoids premature experimental claims

**Cons**

- preserves the exact packaging error the seam identified
- produces no empirical result
- keeps the question rhetorical

**Verdict**

Rejected.

### Option C — Phase 0 Only: Pre-Register And Blueprint

**Description**

Write:

- a frozen pre-registration
- a clean experiment-construction spec

Then stop before sandbox execution.

**Pros**

- converts the philosophical question into a disciplined research object
- prevents premature run contamination
- keeps the next move crisp

**Cons**

- no empirical answer yet
- still requires later construction and execution work

**Verdict**

Recommended.

## Implementation Sketch

### Step 1 — Freeze The First-Run Contract

Use the pre-registration to lock:

- hypothesis
- null
- success criteria
- failure criteria
- invalid/partial classification
- runtime budget
- contamination controls

### Step 2 — Define The Sandbox Construction Protocol

The first sandbox should be an isomorphic historical-constraint problem with:

- renamed variables
- perturbed functional form
- perturbed data shape
- no direct domain labels

The construction protocol should record:

- which source structure was used
- how names were neutralized
- what perturbations were introduced
- what exact curve is the target anchor object

### Step 3 — Define The Independent Contamination Audit

Before execution:

- query a separate model family with the seed problem
- ask what historical phenomenon it resembles

If the verifier identifies the historical source, invalidate the sandbox and rebuild it.

### Step 4 — Register The Prompt Regime

GP-023 must use the actual GP-021 bounded-discriminator profile as currently implemented, including:

- `state_incompatibility`
- `primary_degree_of_freedom`
- `failure_topology`
- `entropy_stripping`
- `dimensional_shift`
- `reciprocal_variable`
- `success_liability`
- `back_pressure`
- `interface_discipline`

Do not add domain hints beyond that.

### Step 5 — Stop Before Execution

Phase 0 ends here.

Do not:

- create the sandbox project
- run iterations
- score outcomes

That belongs to the next execution phase once the protocol is frozen.
